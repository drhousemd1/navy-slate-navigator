# Private message media

Local implementation, not deployed to production. Serve it only with reviewed0900 and the matching RPC clients. It accepts authenticated JPEG, PNG, GIF and WebP files up to5MiB. It validates encoded containers, checksums where applicable and parsed/header dimensions; it does **not** fully decode pixels. It preserves accepted bytes and animation. SVG, remote URLs and other file types are rejected.

`POST /functions/v1/message-media` takes multipart `uploadId`, `expectedRelationshipId`, `expectedRelationshipSessionId`, `file`. It verifies the user bearer with Auth, then invokes service-only `message_media_begin`, stores without overwrite, reads back and hashes exact bytes, and invokes `message_media_finalize`. Only `{attachmentId,mimeType,byteSize,status:'ready'}` returns. Same upload ID and changed bytes is rejected. A lost response can retry exactly; a failure can leave private pending bytes and does not claim a successful upload or delete data.

`GET /functions/v1/message-media/{attachmentId}` verifies the user with Auth, calls service-only `message_media_read`, verifies stored size/hash and returns binary with no-store and a generic filename. Attached access follows actual conversation participants; unattached access is uploader-only. No signed Storage URL, object key or redirect is returned. The service credential is server configuration, never user authentication or response content.

The new `message-media` bucket is private. Existing `message_images` remains unchanged until an explicitly reviewed cutover. The local-only helper `tests/backend/helpers/message-legacy-media.mjs` verifies the private baseline manifest and all13 known objects, reads exactly those object bytes from pinned localhost, registers exact references, and separately performs the guarded cutover. It never fetches manifest URLs, copies objects or deletes objects. `--cutover --endpoint-verified` is an operator assertion that actual authorized/unauthorized endpoint checks have already passed; it is not a substitute for those checks. Missing or quarantined mappings block SQL cutover. Original-account lifecycle/accounting activation and full account deletion remain separate dependencies.

Pure endpoint/validation tests: `deno test --config supabase/functions/message-media/deno.json supabase/functions/message-media/validation.test.ts supabase/functions/message-media/handler.test.ts`. The tests inject mocked internal fetches. Real API tests: `tests/backend/messages-api.test.mjs` require the explicit pinned runtime status, served endpoint and exclusive fixture ownership. They create only disposable accounts/data and remove their own uploads with the Storage API. Deno typecheck,9 mocked/validation tests and12 local API tests passed. The local browser verified image upload, reload, partner access and a masked read-only conversation after unlink. Local cutover denied public access to all13 legacy objects while preserving their bytes; legacy owner permissions were checked through the service helper, not original-account sign-in. Production deployment and account deletion remain unverified.
